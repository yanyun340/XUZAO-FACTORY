# ADR-0004 异常复核接入质检链，而不是新增一条处理通道

状态：已采纳｜日期：2026-11-25｜影响：R09F、R22F｜代码：`backend/src/routes/collab.ts`、`backend/src/routes/flow.ts`

## 背景

现场发现质量问题（例如配件划痕）时，R22F 只允许管理员在异常单上写处理说明并标记解决。这条链路有两个缺陷：

1. 异常单可以独立于质检链关闭，“已处理”没有任何可核对的业务凭证；
2. R09 在 M 口径下只支持全合格，不合格量连录入都要拒绝，问题货物实际上无处安放。

任务包不允许异常成为“自由改状态的旁路”（A29 预期），因此补能力时必须守住这条边界。

## 决定

一、**异常单只引用质检，不写数量、不改订单状态。**

- 新增 `TabletException.qcRecordId`（唯一）与状态 `WAITING_QC`；
- 管理员通过 `POST /exceptions/:id/review` 下发复核，接口只做三件事：把生产任务送入质检（未首检时把 `IN_PRODUCTION` 推到 `PENDING_QC`）、把异常置为 `WAITING_QC`、通知品控；
- 品控录入质检后，系统把同任务下 `WAITING_QC` 且未关联的异常回填 `qcRecordId`；异常单自己永远不参与数量计算。

二、**质检支持多轮与三态决策。**

- `QCRecord` 增加 `round` 与 `parentQcRecordId`：首检可分批（累计不超生产量），返工复检必须指向被判 `REWORK` 的父记录，复检量不超该记录的未复检不合格量；
- `QCDecision` 增加 `scrapQty`：`PASS` 要求不合格为 0，`REWORK`/`SCRAP` 要求不合格 > 0，三种决策的合格量都放行；
- 订单只有在该任务全部检验量都有归宿（放行 + 报废 ≥ 生产量，且无未决策记录）时才转 `QC_DONE`。

三、**质量异常解决必须有凭证，例外要留痕。**

- 关联质检必须 `PASS` 才允许 `RESOLVED`（`EXCEPTION_QC_NOT_PASSED`）；
- 质量异常完全没有关联质检时，必须显式传 `waiveQc: true`（`EXCEPTION_QC_REQUIRED`），写入 `qcWaived` 并进审计；
- `WAITING_QC` 不能通过 `PATCH` 手填（`EXCEPTION_REVIEW_REQUIRED`），只能由复核接口产生。

## 后果

- 异常不再能凭空解决：要么有 PASS 凭证，要么有可审计的豁免记录；
- 部分合格、返工、报废三个原本“未选做”的 F 能力落地，且都与既有数量公式兼容（放行量仍只来自决策记录）；
- 一个生产任务同一时刻只允许一张 `WAITING_QC` 异常（`EXCEPTION_REVIEW_IN_PROGRESS`），避免多张异常对同一批复检各执一词；这是为了保持 M 的单生产任务口径，未做多任务并行；
- 异常仍未覆盖附件与超时升级，不在本 ADR 范围。

## 被否决的方案

- **让异常单直接带合格/不合格数量**：异常就成了可改数量的旁路，违反 A29 预期，也与 R09“品控录入、管理员决策”的职责分离冲突。
- **只加一个“已复核”勾选框**：与现状的“处理说明”没有本质差别，仍然没有凭证。
- **给品控开放异常处置权限**：会把“记录结果”和“决定后续”混在一个角色，破坏 R09 的两步分离。
