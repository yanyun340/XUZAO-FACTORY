# ADR-0002：订单状态与允许动作由后端权威计算

状态：已采纳｜日期：2026-11-04｜决策人：开发者

## 背景

订单主链有 8 个状态、5 种角色和多个数量闸门。如果前端自己判断“下一步能不能点”，页面与接口很容易出现两套规则；弱网重试、多人同时操作时更明显。

## 决策

1. `backend/src/domain/flow.ts` 计算 `FlowQuantities`、`FlowProfit` 与 `allowedActions`。
2. 订单详情返回 `flow` 与 `allowedActions`；前端 `FlowPanel` 只渲染，不推导。
3. 每个流转接口在事务内重新检查角色、状态、记录存在性与数量上限，失败返回稳定错误码（409/422）。
4. 数量一律从业务记录求和，不保存可由前端改写的汇总字段。

## 后果

- 优点：规则单点、可单测；前端增删按钮不会改变安全边界；错误码稳定，测试可直接断言。
- 代价：订单详情查询会带出采购、到货、生产、质检、包装、发货多条子记录；超大订单需要分页或汇总表。
- 约束：新增动作必须同时补 `computeAllowedActions`、路由守卫、domain 测试与权限文档。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 前端用状态机判断 | 两套规则易漂移，且不能作为安全边界 |
| 在订单表冗余汇总数量 | 并发下容易不一致，回填复杂 |
| 用数据库触发器 | 规则难测试、错误码难统一 |
