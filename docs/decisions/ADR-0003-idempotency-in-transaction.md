# ADR-0003：幂等键与业务写入同事务

状态：已采纳｜日期：2026-11-04｜决策人：开发者

## 背景

车间网络不稳定，审批/到货/发货按钮容易被重复点击或超时重试。要求“未确认的写入不能报成功”，且重复提交不能产生两条业务记录。

## 决策

1. 写接口通过 `Idempotency-Key`（8–128 位）声明幂等；作用域为 `(actorId, operation, key)`，有效期 24 小时。
2. `runIdempotent` 在**同一事务**内完成：占位 → 执行回调 → 写入响应 JSON 与资源 ID → 提交。
3. 请求体做规范化 SHA-256；同键不同体返回 409 `IDEMPOTENCY_KEY_REUSED`，首次仍在处理返回 409 `REQUEST_IN_PROGRESS`。
4. 重放返回首次响应，HTTP 200，并加 `Idempotent-Replayed: true`；创建类动作首次为 201。
5. 前端只在真正使用 `runIdempotent` 的路由发送键：订单创建与全部流转动作；同一次业务意图重试时复用同一个键。

## 后果

- 优点：业务记录、时间线、通知、审计、幂等结果要么一起成功，要么一起回滚；重试不会重复建单或重复到货。
- 代价：幂等表会增长，需要按 `expiresAt` 清理（当前未实现定时清理）；前端必须保证“重试复用键、新意图换键”。
- 约束：新增写接口若要求幂等，必须接入 `runIdempotent` 并在 `api-contract.md` 标注。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 只靠数据库唯一约束 | 无法区分“同一次重试”与“新的相同业务” |
| 幂等表独立事务提交 | 业务失败时残留“已完成”记录，重放会返回不存在的成功 |
| 只在前端禁用按钮 | 刷新/多端/超时重试仍会重复提交 |
