## 2. 开场（30 秒）

一句话：序造把一张订单从接单到发货串成可追溯的单据链，每一步的数量与责任人都由服务端校验。

展示顺序：登录页 → 看板 → 订单列表 → 订单详情，指出状态、剩余量、时间线、附件与利润区块。

## 3. 主链演示（3–4 分钟）

| 步骤 | 角色 | 操作 | 讲解点 |
| --- | --- | --- | --- |
| 1 | 管理员 | 新建订单（单产品、数量 100、交期） | 生成 `XZ-YYYYMMDD-0001`；进入待采购 |
| 2 | 管理员 | 创建采购单 | 选供应商与配件；页面标注电镀不启用 |
| 3 | 物流 | 登记到货 60，再登记 40 | 可分批；累计不得超过采购量 |
| 4 | 管理员 | 下发生产 | 未到齐时按钮不出现，直接调接口也会被 422 拒绝 |
| 5 | 生产 | 提交反馈 100 | 只能操作本部门任务 |
| 6 | 管理员 | 下发育检 | 已有反馈才可下发 |
| 7 | 品控 | 录入检验 100 / 合格 100 / 不合格 0 | 不合格大于 0 会被拒绝（F 未实现） |
| 8 | 管理员 | 决策 PASS | 放行量进入可包装剩余 |
| 9 | 管理员 / 包装 | 下发包装 → 登记 100 | 不得超过放行量 |
| 10 | 管理员 / 物流 | 触发发货 → 登记 100 | 足量后状态变已完成，`completedAt` 写入 |

每步切换后刷新详情页，强调“按钮由后端 `allowedActions` 决定”。

## 4. 失败与边界演示（1–2 分钟）

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 越权 | 物流账号访问用户管理或审计 | 403，页面提示无权限 |
| 越级 | 对待采购订单直接调包装下发 | 409 `ORDER_STATUS_CONFLICT` |
| 超量 | 到货/包装/发货填写超过剩余量 | 422，记录不落库 |
| 重复提交 | 同一 `Idempotency-Key` 重放采购请求 | 200 + `Idempotent-Replayed: true`，不重复建单 |
| 并发库存 | 展示测试报告中的 20 并发扣减 | 成功 15、冲突 5，最终 0，流水 15 条 |
| 金额脱敏 | 生产/物流账号查看订单详情 | 无利润区块，客户联系方式隐藏 |
| 弱网草稿 | 新建订单填一半刷新 | 恢复草稿提示 |

## 6. 常见提问与回答要点

| 问题 | 回答 |
| --- | --- |
| 为什么不做多产品？ | M 允许单产品；先保证数量闸门与状态机正确，多产品是 F，未选做，状态表已写明 |
| 电镀怎么处理？ | M 不支持；采购表单明确标注未启用，不记录镀层、不计成本 |
| 撤销怎么办？ | 不做删除；状态守卫拒绝越级操作，误操作走人工修正，避免破坏审计 |
| 幂等怎么保证？ | `(actorId, operation, key)` + 请求哈希，与业务写入同事务；重放返回首次响应 |
| 库存并发？ | 单条 `UPDATE ... WHERE quantity + delta >= 0 RETURNING`，测试 20 并发；首次建档 8 并发 |
| 为什么用内嵌 PostgreSQL？ | 干净环境可复现、无管理员权限；代价是首次复制约 108MB，备份用逻辑 JSON |
| 备份能恢复吗？ | 已恢复到新隔离库与隔离附件目录，逐表与 SHA-256 核对；护栏防止覆盖现有库 |
| 哪些没做？ | 多产品、电镀、返工/报废、10 分钟撤销、Excel 导入、离线队列、远程部署；见状态表 |
| AI 做了什么？ | 起草与缺陷定位建议；本人阅读、修改、运行与验证，详见 `docs/ai-collaboration.md` |
