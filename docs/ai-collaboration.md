# AI 协作与本人工作说明

版本：0.2.0｜更新：2026-11-14
目的：满足 R27 对“真实 AI 修改证据”的要求，说明哪些由 AI 辅助、哪些由本人完成、如何验证，以及哪些 AI 建议被拒绝或修正。

## 1. 使用范围

AI 作为结对助手参与：需求梳理、代码起草、文档起草、缺陷定位建议、测试用例建议。以下工作由本人完成或最终确认：

- 需求理解与范围取舍（M/F 边界、拒绝规则）。
- 技术选型与目录结构。
- 所有代码的阅读、修改、运行与调试。
- 测试的实际执行、失败分析与修复确认。
- 数据库迁移、种子、备份恢复演练的实际操作。
- 文档中的数字、路径、命令与结论核对。

AI 输出不直接作为“已完成”证据；证据以 `tests/reports/` 与可复现命令为准。

## 3. 被拒绝或修正的 AI 建议

| 建议 | 未采用原因 |
| --- | --- |
| 用前端状态机判断下一步按钮 | 会形成两套规则，且不能作为安全边界；改为后端 `allowedActions` |
| 在订单表冗余汇总数量 | 并发下易不一致；改为从业务记录求和 |
| 为通过测试放宽断言/跳过失败用例 | 违反考核底线；失败保留并修复实现 |
| 用 `pg_dump` 做备份 | 内嵌发行版没有该工具；改用逻辑 JSON + 附件目录 |
| 直接把恢复指向开发库“省事” | 违反“恢复到新隔离环境”；保留护栏并新建隔离库 |
| 把未做的 F 写成“基本完成” | 状态表如实标注未选做与部分实现 |

## 5. 可解释性自检

- 每个业务规则都能指向具体文件与测试，而不是“AI 说可以”。
- 每个“已验收”都有命令、时间与输出；人工核对单独标注。
- 已知缺口在 `docs/feature-status.md` 与 `tasks/todo.md` 中可见。
- 涉及安全的选择（认证、授权、幂等、并发、恢复护栏）均有代码与测试双重落点。
