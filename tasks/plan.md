# 执行计划

项目：序造 XuZao｜开始：2026-11-03｜当前：2026-11-04｜版本：0.1.0

## 1. 目标与交付定义

在第三轮考核周期内独立完成一套可本地运行的工厂订单协同系统，覆盖 R01–R27 的 M 要求，按证据申报所选 F，并提交源码、文档、测试与备份恢复演练。

“完成”的定义：

1. 干净环境按 README 能启动，健康检查通过。
2. 订单主链可走完，越权/超量/重复提交被服务端稳定拒绝。
3. 自动化测试全部实际通过，报告可复现。
4. 数据库与附件能恢复到新的隔离环境并核对一致。
5. 文档能解释范围、取舍、接口、数据与已知缺口。

## 3. 工作分解

### P0 认知与范围（已完成）

- 阅读任务书、范围矩阵、验收场景与文档样例。
- 确定栈：Node 24 + TS ESM + Fastify 5 + Prisma 7 + PostgreSQL 18 + React 19 + Vite 6。
- 确定单产品 M 闭环；F 只选 R01F、R20F、R23F。

### P1 骨架与身份（已完成）

- workspace + 内嵌 PostgreSQL（中文路径转到用户目录）。
- 迁移与合成种子；演示账号。
- scrypt、会话、`sessionVersion`、角色守卫；统一错误信封与 requestId。
- 测试隔离：`TEST_DATABASE_URL` 强制含 `test`，global setup 迁移 + 清表。

### P2 主链（已完成）

- 状态机 8 状态；数量公式；`computeAllowedActions`。
- 采购、到货、生产下发/反馈、质检录入/决策、包装下发/登记、发货触发/登记。
- 订单号 `XZ-YYYYMMDD-0001`；时间线；完成判定。
- 详情页 `FlowPanel` 只渲染后端动作。

### P3 配套能力（已完成）

- 通知、未读筛选、全部已读；交期提醒任务。
- 看板、异常上报、审计检索、附件、订单导出。

### P4 可靠性与环境（已完成）

## 5. 验收演练顺序

1. 干净目录 `npm install` → 配置 → `migrate` → `seed` → `dev`。
2. 健康检查；五角色登录。
3. 完整订单主链；越权、超量、重复提交。
4. 并发库存与并发建档。
5. 备份 → 新隔离库 + 隔离附件目录恢复 → 行数/附件核对。
6. 前端构建、类型检查；桌面与 390px 截图。
7. 对照 `docs/feature-status.md` 与 `tests/reports/` 逐项说明。
